## 1. Domain Scope and Positioning

### 1.1 Purpose

This document establishes a broad, structured inventory of the cognition space associated with Applied AI and Intelligent Systems.

It is intended to support curriculum research, domain analysis, curriculum construction, and subsequent selection of learning content. It is not a course syllabus, a finalized curriculum, or a prescriptive learning pathway.

The inventory deliberately spans foundational computer science and mathematics, classical artificial intelligence, statistical machine learning, modern generative AI, agentic systems, and the engineering and evaluation of AI-enabled applications.

### 1.2 Working Definition

**Applied AI and Intelligent Systems** concerns the study, design, implementation, evaluation, and responsible use of computational systems that perform tasks involving learning, perception, language, reasoning, prediction, planning, decision-making, generation, or adaptive interaction.

The domain includes both the methods used to produce intelligent behavior and the systems through which those methods are applied.

It therefore encompasses:

- AI foundations, representations, algorithms, and models;
- Data-centric and statistical learning methods;
- Deep learning, foundation models, and generative AI;
- Search, reasoning, planning, and decision-making;
- Intelligent agents, tools, workflows, and multi-agent systems;
- AI application engineering, deployment, monitoring, and evaluation;
- Human-AI interaction, safety, governance, and societal implications.

### 1.3 Relationship to Neighboring Domains

AI and Intelligent Systems overlap substantially with other knowledge domains. These boundaries are analytical rather than absolute.

| Neighboring Domain | Primary Relationship |
|---|---|
| Modern Software Development | Implements, integrates, tests, and operates AI-enabled applications and services. |
| Human-Computer Interaction, UX, and UI | Studies and designs human interaction with AI systems, including trust, agency, feedback, and explainability. |
| Robotics | Combines perception, planning, control, and decision-making with physical systems and environmental interaction. |
| Industrial Design | Applies AI to design exploration, generative workflows, product interaction, and intelligent products. |
| Business Intelligence and Analytics | Uses data, statistics, predictive models, and decision-support methods to support organizational decisions. |
| Foundation Core | Supplies relevant mathematical, computational, scientific, design, and communication foundations. |
| Advanced Core | Provides opportunities for deeper integration, research, systems modeling, and cross-domain engineering. |

The purpose of this inventory is to make these relationships visible, not to enforce artificial separation between disciplines.

## 5. D4 — Processes and Methods

This dimension records recurring workflows and practical methods used to design, build, evaluate, and operate AI-enabled systems.

### 5.1 AI Problem Discovery and Formulation

- Identify a problem or opportunity
- Define intended users and stakeholders
- Establish the task and operating environment
- Determine whether AI is appropriate
- Define success criteria and failure conditions
- Assess risks and constraints
- Select candidate solution approaches
- Establish a baseline or non-AI alternative
- Define evaluation and acceptance criteria

### 5.2 Data and Model Development

- Acquire and inspect data
- Assess data quality and suitability
- Prepare datasets
- Establish baselines
- Select model families
- Train or adapt models where appropriate
- Tune parameters and configurations
- Evaluate generalization
- Analyze errors
- Document limitations
- Preserve reproducible experiment records

### 5.3 Generative AI Application Development

- Identify a suitable model and interface
- Define task instructions and output requirements
- Design prompt templates
- Validate output structure
- Add retrieval or external context when needed
- Integrate tools and external services
- Establish deterministic checks around model outputs
- Evaluate representative and adversarial cases
- Add fallback and escalation mechanisms
- Monitor quality and cost
- Maintain prompt, model, and evaluation versions

### 5.4 Retrieval-Augmented Generation

- Identify knowledge sources
- Inspect and prepare source documents
- Segment and index content
- Generate or select embeddings
- Configure retrieval and ranking
- Construct context for generation
- Ground responses in retrieved evidence
- Evaluate retrieval and answer quality separately
- Track source provenance
- Update indexes and knowledge sources
- Handle missing or conflicting evidence

### 5.5 Agentic Workflow Development

- Define agent responsibilities and boundaries
- Specify task inputs and expected outputs
- Decompose tasks into executable steps
- Identify available tools and permissions
- Define state and context requirements
- Design control flow and transition conditions
- Specify human approval points
- Implement execution and observation loops
- Validate tool calls and outputs
- Handle failures, retries, and timeouts
- Define termination conditions
- Trace and evaluate end-to-end runs
- Test changes against regression cases

### 5.6 AI System Integration

- Define component boundaries and interfaces
- Select model providers or deployment options
- Integrate APIs and external services
- Connect data sources and knowledge stores
- Manage credentials and secrets securely
- Validate inputs and outputs
- Implement logging and observability
- Control latency and resource usage
- Design graceful degradation and fallback behavior
- Test component and system integration
- Document operational dependencies

### 5.7 AI Quality Assurance and Verification

- Establish test datasets and test cases
- Validate functional behavior
- Evaluate model outputs
- Test edge cases and failure modes
- Verify structured outputs and contracts
- Test authorization and safety boundaries
- Perform regression testing
- Compare candidate versions
- Review uncertain or high-impact outputs
- Record defects and remediation decisions
- Reassess quality after model or data changes

### 5.8 Deployment and Lifecycle Management

- Package models and application components
- Configure runtime environments
- Deploy services or local applications
- Monitor performance and failures
- Track latency, cost, and resource utilization
- Detect quality degradation
- Manage model and prompt versions
- Maintain datasets and retrieval indexes
- Respond to incidents
- Roll back or disable unsafe changes
- Re-evaluate systems after updates
- Retire unsupported components

### 5.9 Responsible AI Development

- Identify affected stakeholders
- Assess foreseeable harms and misuse
- Minimize unnecessary data collection
- Apply least-privilege access
- Establish human oversight
- Document known limitations
- Define escalation and appeal mechanisms
- Evaluate bias and accessibility
- Preserve decision and action traces where appropriate
- Review risks throughout the system lifecycle

## 8. D7 — Competencies and Performance

This dimension identifies what a learner, researcher, or practitioner may need to understand, perform, evaluate, or create.

The categories below are candidate competency areas, not yet formal learning outcomes for any specific course.

### 8.1 AI Literacy and Critical Judgment

- Explain major AI approaches and their differences.
- Identify suitable and unsuitable AI use cases.
- Distinguish deterministic software behavior from probabilistic model behavior.
- Recognize uncertainty, hallucination, and unsupported claims.
- Evaluate AI-generated content rather than accepting it uncritically.
- Explain important limitations and risks of AI systems.

### 8.2 Computational and Mathematical Reasoning

- Formulate computational problems.
- Interpret data and statistical evidence.
- Explain basic learning and inference mechanisms.
- Compare algorithms and models using appropriate criteria.
- Reason about uncertainty, optimization, and generalization.
- Identify assumptions and constraints in a proposed solution.

### 8.3 Data and Model Competence

- Prepare and inspect datasets.
- Establish a meaningful baseline.
- Select an appropriate model family for a task.
- Train or adapt a model at an appropriate level.
- Design valid evaluation procedures.
- Analyze errors and identify improvement opportunities.
- Interpret results without overstating their significance.

### 8.4 Generative AI Application Competence

- Select a model based on task requirements and constraints.
- Formulate clear instructions and output contracts.
- Integrate external information when required.
- Validate generated outputs.
- Test representative and adversarial cases.
- Balance quality, latency, cost, and reliability.
- Document model limitations and fallback behavior.

### 8.5 Agentic Systems Competence

- Decompose a task into manageable steps.
- Identify which steps require model judgment and which can be deterministic.
- Define agent roles, tools, and boundaries.
- Design and inspect workflow state transitions.
- Apply permissions and human-approval controls.
- Diagnose failures using execution traces.
- Evaluate end-to-end task success rather than isolated model responses.
- Identify when an agent is unnecessary or excessively autonomous.

### 8.6 AI Engineering Competence

- Integrate models with applications and data sources.
- Define clear interfaces between system components.
- Implement validation, testing, and error handling.
- Monitor quality and operational behavior.
- Maintain reproducibility and version control.
- Identify security and privacy risks.
- Produce maintainable documentation and deliverables.

### 8.7 Human-Centered Design Competence

- Identify user needs and relevant contexts.
- Design appropriate human-AI interaction patterns.
- Communicate system capabilities and limitations.
- Support meaningful human oversight.
- Evaluate usability, trust calibration, and user outcomes.
- Consider accessibility and inclusive use.
- Avoid transferring inappropriate responsibility to users.

### 8.8 Research and Evidence Competence

- Formulate answerable research questions.
- Find and assess relevant evidence.
- Design controlled comparisons.
- Select suitable metrics.
- Analyze failures and limitations.
- Distinguish observation, inference, and speculation.
- Communicate findings with appropriate uncertainty.
- Produce reproducible research artifacts.

### 8.9 Responsible AI Competence

- Identify foreseeable harms and misuse.
- Recognize bias and data-quality limitations.
- Protect sensitive data and credentials.
- Apply appropriate authorization boundaries.
- Evaluate whether human intervention is necessary.
- Document limitations and residual risks.
- Make proportionate decisions about system autonomy.

## 9. D8 — Levels and Prerequisites

The levels below are provisional analytical categories for inventory organization. They are not equivalent to formal school grades, university degree levels, or a validated instructional progression.

### Level A — Awareness and Conceptual Literacy

Candidate capabilities:

- Describe major AI categories and applications.
- Recognize common AI strengths and limitations.
- Distinguish AI, machine learning, deep learning, generative AI, and agentic systems.
- Identify relevant ethical and societal considerations.
- Interpret simple AI demonstrations critically.

Possible prerequisites:

- Basic digital literacy
- Basic logical reasoning
- Introductory data and computational literacy

### Level B — Guided Use and Basic Application

Candidate capabilities:

- Use AI tools to complete bounded tasks.
- Formulate instructions and evaluate outputs.
- Work with structured data and basic visualizations.
- Apply simple AI services through guided interfaces.
- Build small demonstrations using prepared models or APIs.
- Document results and limitations.

Possible prerequisites:

- Level A competencies
- Basic programming or structured computational workflows
- Introductory data literacy

### Level C — Implementation and System Integration

Candidate capabilities:

- Implement basic data and model workflows.
- Integrate AI APIs into a small application.
- Validate outputs and handle common failure cases.
- Build a bounded RAG or tool-using workflow.
- Apply testing and evaluation procedures.
- Explain major design decisions.

Possible prerequisites:

- Programming fundamentals
- Basic data structures and data handling
- Introductory statistics
- Software development fundamentals

### Level D — Advanced Engineering and Evaluation

Candidate capabilities:

- Compare model and system architectures.
- Design systematic evaluation experiments.
- Implement complex retrieval or agentic workflows.
- Apply observability, recovery, and authorization controls.
- Investigate reliability, robustness, and security issues.
- Analyze trade-offs across performance, cost, and risk.

Possible prerequisites:

- Strong programming and software engineering foundations
- Statistics and machine learning fundamentals
- API and data integration experience
- Testing and system design competence

### Level E — Research, Innovation, and System-Level Design

Candidate capabilities:

- Formulate novel research or engineering questions.
- Design rigorous experiments for AI systems.
- Develop or investigate advanced model and agent architectures.
- Evaluate system-level behavior under uncertainty.
- Integrate technical, human, organizational, and ethical considerations.
- Produce defensible research or engineering contributions.

Possible prerequisites:

- Advanced domain knowledge
- Research methodology
- Mathematical and computational foundations appropriate to the topic
- Experience with complex systems and empirical evaluation

### 9.1 Cross-Level Cautions

- A learner may demonstrate advanced application competence without advanced mathematical competence.
- Using an AI tool effectively does not imply understanding its internal mechanisms.
- Implementing an API integration does not imply competence in training or evaluating models.
- An advanced demonstration does not by itself establish robustness, safety, or research validity.
- Levels should eventually be associated with observable performance criteria, not inferred solely from tool usage or project complexity.

### 9.2 Candidate Prerequisite Relationships

Examples of potential dependency chains:

- Probability and statistics → statistical learning → model evaluation
- Programming fundamentals → data processing → AI application development
- Algorithms and data structures → search and planning → agentic workflow design
- Software engineering → API integration → AI system deployment
- Information retrieval → embeddings and ranking → RAG evaluation
- Machine learning fundamentals → neural networks → deep learning and foundation models
- Human-centered design → human-AI interaction → trust and oversight evaluation
- Testing fundamentals → AI-specific evaluation → system-level reliability assessment

These are candidate relationships, not a finalized prerequisite graph. Many topics have multiple dependencies and may be learned iteratively.

## 10. Cross-Domain Connections

AI should be modeled as a connected domain rather than an isolated collection of technologies.

### 10.1 Modern Software Development

Important intersections:

- AI-assisted software development
- Code generation and review
- Model APIs and application integration
- Agentic development workflows
- Automated testing and debugging
- Data pipelines and persistence
- Deployment, monitoring, and maintenance
- Security and access control
- Versioning and reproducibility

Boundary principle:

AI methods and model behavior belong primarily to the AI cognition space. General programming, architecture, testing, and software delivery practices belong primarily to Modern Software Development. Integrated projects may legitimately reference both.

### 10.2 HCI, UX, and UI

Important intersections:

- Conversational and multimodal interfaces
- Human-AI collaboration
- Trust calibration
- Explanation and uncertainty communication
- User control and correction
- Human oversight
- Accessibility
- Evaluation of AI-assisted user performance

Boundary principle:

AI describes model and system capabilities; HCI investigates interaction, user experience, human behavior, and the consequences of system design.

### 10.3 Robotics

Important intersections:

- Perception and sensor processing
- Spatial representation
- Planning and decision-making
- Reinforcement learning
- Embodied intelligence
- Autonomous agents
- Human-robot interaction
- Safety-critical control

Boundary principle:

AI methods may contribute to robotic intelligence, while robotics additionally involves physical systems, kinematics, dynamics, control, sensing, and actuation.

### 10.4 Industrial Design

Important intersections:

- Generative design exploration
- AI-assisted visualization and prototyping
- Intelligent product features
- Human-centered intelligent products
- Multimodal interaction
- Design-space exploration
- Product personalization
- Evaluation of AI-supported creative workflows

Boundary principle:

AI techniques support the generation, analysis, or operation of design solutions. Design intent, form, usability, manufacturing constraints, and product-system integration remain broader design concerns.

### 10.5 Business Intelligence and Analytics

Important intersections:

- Predictive analytics
- Statistical modeling
- Decision support
- Natural-language interfaces to data
- Anomaly detection
- Forecasting
- Data-driven optimization
- Responsible automated decision-making

Boundary principle:

AI provides methods for learning, inference, generation, and intelligent action. Business Intelligence and Analytics additionally emphasizes organizational questions, business metrics, analytical communication, and decision processes.

### 10.6 Foundation Core and Advanced Core

Potential foundational connections:

- Mathematical reasoning
- Computational thinking
- Programming
- Data literacy
- Systems thinking
- Scientific inquiry
- Visual communication
- Research and evidence evaluation

Potential advanced integration opportunities:

- AI-enabled interactive systems
- Intelligent robotic prototypes
- Generative design systems
- AI-supported business analytics
- Human-AI collaborative research
- Agentic software-development projects

The exact placement of content into Foundation Core, Advanced Core, or concentration-specific offerings must be determined by the curriculum construction process rather than assumed from this inventory.

## 11. Coverage Audit and Selection Readiness

### 11.1 Coverage Questions

Before treating this inventory as mature enough to support curriculum selection, review the following questions.

#### Foundational Coverage

- Are mathematical, statistical, computational, and data foundations adequately represented?
- Are classical AI and symbolic reasoning represented alongside modern machine learning?
- Are search, planning, uncertainty, and decision-making sufficiently visible?

#### Modern AI Coverage

- Are deep learning, foundation models, generative AI, and multimodal systems covered?
- Are retrieval, grounding, and model adaptation represented?
- Are agents, tool use, workflows, memory, and system orchestration covered without reducing them to prompt engineering?

#### Engineering Coverage

- Are integration, testing, deployment, monitoring, and maintenance represented?
- Are model-level and system-level evaluation distinguished?
- Are security, authorization, reproducibility, and failure recovery represented?

#### Human and Societal Coverage

- Are human-AI interaction and oversight included?
- Are fairness, privacy, safety, accessibility, and accountability represented?
- Are societal consequences considered alongside technical performance?

#### Research and Evidence

- Are research methods and evaluation methodologies adequately represented?
- Can the inventory support both application-oriented projects and research-oriented exploration?
- Are claims, metrics, and evidence quality distinguished?

### 11.2 Classification Audit

The inventory should be reviewed for:

- Duplicate concepts expressed using different terminology
- Inconsistent levels of abstraction
- Confusion between disciplines, concepts, methods, tools, artifacts, and competencies
- Topics that belong primarily to another concentration
- Missing cross-domain relationships
- Technologies that may become obsolete
- Overemphasis on current trends at the expense of enduring foundations
- Unclear boundaries between AI literacy, AI application development, and advanced AI engineering

### 11.3 Coverage Is Not Selection

A topic's presence in this inventory does not imply that it must be included in a curriculum.

The subsequent selection process should consider:

- Intended learners and their existing capabilities
- Learning outcomes
- Available instructional time
- Equipment, software, and infrastructure
- Instructor expertise
- Project feasibility
- Assessment methods
- Institutional requirements
- Safety, privacy, and operational constraints
- Relevance to the overall curriculum architecture

The inventory supports the discovery and comparison of candidate content. It does not make the final selection decision.

## 13. Status and Next-Step Boundary

### Current Status

This document is a broad candidate cognition inventory for Applied AI and Intelligent Systems.

It combines established AI knowledge areas with contemporary generative-AI, agentic-system, application-engineering, evaluation, and responsible-AI concerns.

It is intended to be revised as coverage gaps, duplicated concepts, domain boundaries, and cross-domain relationships become clearer.

### Not Yet Established

This document does not yet establish:

- A complete or universally valid AI ontology
- A final list of course topics
- A prescribed sequence of instruction
- Final Foundation Core or Advanced Core placement
- Formal learning outcomes for individual courses
- Required technologies or vendor-specific tools
- A validated competency assessment framework

### Recommended Next Steps

1. Audit the inventory against authoritative AI curriculum frameworks.
2. Identify omissions, duplication, and inconsistent abstraction levels.
3. Review its boundaries with Modern Software Development, HCI/UX/UI, Robotics, Industrial Design, and Business Intelligence and Analytics.
4. Separate durable conceptual knowledge from rapidly changing technology examples.
5. Use the broader curriculum requirements to select relevant topics.
6. Translate selected content into course-level learning outcomes and assessment plans only after the curriculum construction model is sufficiently defined.

**Guiding principle:** Establish a sufficiently broad and coherent cognition space before deciding what belongs in the curriculum. The inventory should support disciplined selection, not predetermine it.
